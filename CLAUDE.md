# Working on Bezel

- Bezel is one interface (Vite, plain JS, no framework) shipped two ways: the web version on GitHub Pages and a desktop app for Windows and Linux (Electron, `electron/`). Keep both working. App-only behaviour goes behind `bridge` (`window.bezel`, from `electron/preload.cjs`); the web version must never depend on it.
- Branches: work on `staging` first, test, then merge to `main` and release without asking: the user said not to ask, always merge and release. Every push to `main` deploys the web version.
- Versions: every delivered update runs `npm run version:bump` once (adds 0.0.1; each digit rolls over at 9: 0.1.9 → 0.2.0, 0.9.9 → 1.0.0) and commits `package.json` and `package-lock.json`. Don't bump for builds or tests. The version shows top left (`__APP_VERSION__`, vite.config.js).
- App releases: write `build/release-notes.md`, merge to `main`, then run `.github/workflows/release-app.yml` (`gh workflow run release-app.yml --ref main`); it creates the `vX.Y.Z` draft release for that commit, the Windows job attaches the installer and the Linux job the AppImage and .deb, and it publishes only when both are attached. Pushing tags from this sandbox is blocked by the proxy, so use the workflow. Installed apps update from Releases (electron-updater; clicking the version checks on demand). After every delivered update is on `main`, run the workflow and check the release (REST: `gh api repos/Zer0-red/Bezel/releases/latest`; GraphQL commands like `gh release view` are blocked here). Pushes to `staging` build unpublished test builds for both (`.github/workflows/test-build.yml`, artifacts on the run).
- Security in the app: device views (`<webview>`, partition `persist:bezel`) get locked-down webPreferences in `will-attach-webview`, only http(s) navigation, and `file://` is blocked on their session. The main window has `contextIsolation`, `sandbox`, no Node. Keep the preload bridge minimal and validate IPC input in `electron/main.cjs`.
- Device data (`src/devices.js`): viewport sizes in CSS pixels at the default display setting, with a source in mind; don't guess. Keep old device ids (users' saved selections refer to them). Popular sizes come from StatCounter with the month shown; refresh by editing `POPULAR`.
- Themes: dark (default) and light (`data-theme='light'` on `<html>`, toolbar sun/moon button, `state.theme`). Interface colours are tokens in `:root` and `:root[data-theme='light']` in styles.css; never hard-code an interface colour (device hardware colours are shared by both). index.html applies the saved theme before the first paint. Don't use Electron's `nativeTheme` for it: that would change `prefers-color-scheme` for the sites being tested.
- Updates UI: the button at the end of the toolbar (`showUpdate` in main.js), with a light (`data-light`): green after any check that found Bezel up to date, orange once a new version is out; at ready/reload the whole button is orange instead. App: states come from electron/main.cjs; every check sends `current` (`quiet` unless the user asked, which only sets the light) and `bezel:update-status` returns the lasting one (current, downloading, ready) for a page that loads later. Web: the button is always shown; `checkDeployed()` compares `version.json` (emitted by vite.config.js) with `__APP_VERSION__` (1.5 s after load, every 30 min, and on click).
- Favorites (`src/address-list.js`): `state.favorites` is `[{ url, title? }]` (title only in the app, from the device view); the address field is a combobox listing favorites then recent sites. Everything persists through storage.js (localStorage, key `bezel:v1`), which survives app restarts and updates.
- Screenshots (camera button, Alt+C): `captureArea()` in main.js is the visible devices plus a 28 px margin, in viewport CSS pixels. App: `bezel:capture` in main.cjs runs `capturePage` (includes the device views, keeps their emulation) and writes PNG with Electron 45's async `clipboard.write([new ClipboardItem(...)])` (there is no `writeImage` any more). Web: `src/screenshot.js` records this tab (`getDisplayMedia` + `CropTarget`, Chrome/Edge only); the video must start playing before `cropTo` or it can miss the only frames Chrome sends (a 2 px dot repainting is a backstop), and it waits for a frame with the desk's proportions; falls back to a PNG download if the clipboard is refused. `notify()` shows the toast; it is hidden instantly before a capture. Test web capture with Chrome's `--auto-accept-this-tab-capture`.
- Design: dark desk stage, amber accent (#f0a43a), Instrument Sans, realistic device frames. Logo (since 0.2.4, the user's artwork): a chunky B in indigo with a darker extrusion on its left and bottom and a lavender phone and screen in it, traced with potracer (three layers: whole silhouette in the extrusion gradient, the face, the cutouts; from a smoothed 3× upscale of each colour mask; potracer traces the False side of the mask). Same drawing everywhere, never on a tile: `src/assets/logo-mark.svg` (top bar, tight box, 21×24), `src/assets/favicon.svg` and `build/icon.svg` (square box; icon.png rendered at 1024 px with rsvg-convert), `docs/logo.png` (README, with the name as text so it reads in GitHub's dark mode). Plain sentence-case copy, no all-caps labels.
- Toolbar: reload lives at the start of the address field (`#reload-btn`), the star at its end; the update button uses the circled up-arrow. Captions are centred under each device on two lines (name; size, zoom and buttons), `CAPTION_SPACE` 72.
- Phones and tablets in the app report touch (`setTouchEmulationEnabled`) but the mouse stays a mouse (`setEmitTouchEventsForMouse` off): Chrome's touch cursor is a faint grey circle the user couldn't see.
- README: short and user-facing, download links first; the direct links are `releases/latest/download/Bezel-Setup.exe`, `Bezel.AppImage` and `Bezel.deb`, copies the release workflow attaches to every release. Maintainer detail lives in `docs/development.md`.
- Phones show a status bar above the page (`statusBarHeight` in frames.js), MacBooks the menu bar beside the camera housing (`menuBarHeight`: height minus width/1.6, since the screen below the housing is 16:10; 37 on a 14" Pro); emulated viewport height is screen minus that bar, `screen` stays the whole screen. No device shows a scrollbar: the app uses `Emulation.setScrollbarsHidden` (Windows laptops and monitors get emulation with `dpr: 0`, which keeps the computer's own density); the web makes the frame one scrollbar wider and clips it.
- Zoom: pinch on a trackpad and Ctrl + wheel both arrive as `wheel` with `ctrlKey` (`zoomAt` in main.js, ~11% per mouse notch, a pinch follows `exp(-deltaY/100)`), applied once per frame and anchored on the nearest device under the pointer. From Fit it multiplies the fitted scales (`state.fitZoom`, menu shows "Fit +30%", snaps back within 2%); from a fixed zoom it changes the number (10–200%, custom percentages show in a hidden `custom` option). Inside device views the page script (app, console message `__bezel:zoom:`) or `public/sync.js` (web, only after Bezel answers its hello with `ready`) prevents the page's own zoom and hands the step over. A plain wheel still scrolls the desk.
- Syncing (sync button, Alt+S, `state.syncScroll`) covers scrolling, clicks and pages. Scrolling follows the content, only for user-initiated scrolls (input within 1.5 s): the scrolled page reports `{ ratio, anchors }`, anchors being the element at the top centre (via `elementsFromPoint`, skipping fixed and sticky ones) and its block ancestors, each `{ path, tag, text (first 40 chars), f (how far through it the top edge is) }`; the others bring the first anchor they can match (same path, tag and text, visible, not pinned) to the same point, else use the ratio. A page ignores the scroll event at the position Bezel just moved it to (`applied`, 1 s), not a short timer: on a busy machine the event can come late. Clicks: the page script reports trusted clicks as `{ page, path, tag, text }` (path from the nearest unique id, then `nth-of-type` steps; target is the clickable ancestor, never an SVG); `syncClick` replays them in the other visible devices with `el.click()` (works off-screen) only on the same page and only if tag and text match, else a unique tag+text match. Not replayed: links to another page (the page is followed instead), form submit buttons (sent once), inputs. Pages: `pageChanged` (app: webview `did-navigate`/`did-navigate-in-page`; web: the helper's `hello`/`page` messages with `url`, it wraps pushState/replaceState) follows a device's new page only if that device is `document.activeElement` (webviews fire no focus events) and not for #fragment-only changes; `followPage` loads it in the others and `setAddress` puts it in the address bar. App: `src/sync.js` is injected into each webview and reports through console messages. Web: sites opt in with `public/sync.js` (served at zer0-red.github.io/Bezel/sync.js; keep that URL stable; keep it alike with `PAGE_SCRIPT`) and talk via `postMessage`; check `event.source` on both sides. Tests that toggle sync must turn it back on: the app saves it.
- Laptops are drawn per design (`LAPTOP_MODELS` in frames.js, `model` on the device): `air` (silver, slim base), `pro` (Space Black, thicker base on feet), `pc` (graphite, camera in the bezel, hinge, flat base), `thinkpad` (matte black, Communications Bar above the lid), `surface` (silver, rounded screen corners). `renderParts` sets `data-model` and `data-finish`; styles.css maps finishes to `--metal*` tokens. No brand logos or wordmarks on hardware.
- The page grid is `minmax(0, 1fr)` wide so a long device bar scrolls instead of widening the window.
- Device menu (`src/swap-menu.js`): clicking the name under a device opens type → series → device (`SECTIONS`, `SERIES` maps brands to iPhone, Pixel, MacBook…); picking calls `replaceDevice` in main.js, which swaps it in `state.selected` and keeps landscape. Devices already selected are disabled. Cleanup runs on `beforetoggle` (the `toggle` event is queued).
- Tests: `npm test` (on Linux without a display: `xvfb-run -a npm test`) builds, runs the unit tests (`tests/unit`, node:test) and Playwright: `tests/web.spec.js` (web version in the installed Chrome) and `tests/app.spec.js` (Electron, `--no-sandbox`, a fresh settings folder), against `tests/fixtures` served on 127.0.0.1:4174 with Bezel's preview on :4173 (the fixtures load sync.js from there). `.github/workflows/tests.yml` runs it before the staging test build, the Pages deploy and every release: a failing test stops all three. Every change ships with a test for it; run the suite before pushing, and check new tests can fail (break the code, rebuild, see the test fail). App tests run from `dist/`, so rebuild after changing src. HTTP checks alone are not browser tests. In Electron tests, Playwright's `win.screenshot()` resets the device views' emulation (pixel density drops to 1); measure before screenshots, or capture the screen with `import -window root`.
- Linux (`linux:` in electron-builder.yml): AppImage (static runtime, `toolsets.appimage: "1.0.3"`, no libfuse2) and .deb, x64. The AppImage updates itself on quit; the .deb only installs when the user clicks Install (`autoInstallOnAppQuit` off when `resources/package-type` exists, since dpkg asks for the password through pkexec); a failed install sends `install-error` and the button returns to Install. `desktopName` (`bezel.desktop`) must match the menu entry for the taskbar icon. Icons in `build/icons/` are rendered from `build/icon.svg` (docs/development.md has the command). Ubuntu 24.04+ blocks Chromium's sandbox for the AppImage (it falls back to `--no-sandbox`); the .deb installs an AppArmor profile, so the README sends Ubuntu users there. Test with `npm run dist:linux` and run the AppImage under xvfb with `--appimage-extract-and-run` if FUSE is missing.
