# Working on Bezel

- Bezel is one interface (Vite, plain JS, no framework) shipped two ways: the web version on GitHub Pages and a Windows app (Electron, `electron/`). Keep both working. App-only behaviour goes behind `bridge` (`window.bezel`, from `electron/preload.cjs`); the web version must never depend on it.
- Branches: work on `staging` first. Merge to `main` only when the user approves; every push to `main` deploys the web version.
- Versions: every delivered update runs `npm run version:bump` once (adds 0.0.1; each digit rolls over at 9: 0.1.9 → 0.2.0, 0.9.9 → 1.0.0) and commits `package.json` and `package-lock.json`. Don't bump for builds or tests. The version shows top left (`__APP_VERSION__`, vite.config.js).
- Windows app releases: write `build/release-notes.md`, merge to `main`, then run `.github/workflows/release-app.yml` (`gh workflow run release-app.yml --ref main`); it creates the `vX.Y.Z` draft release for that commit, attaches the installer and publishes it. Pushing tags from this sandbox is blocked by the proxy, so use the workflow. Installed apps update from Releases (electron-updater; clicking the version checks on demand). Release only when the user asks. Pushes to `staging` build an unpublished test installer (`.github/workflows/test-build.yml`, artifact on the run).
- Security in the app: device views (`<webview>`, partition `persist:bezel`) get locked-down webPreferences in `will-attach-webview`, only http(s) navigation, and `file://` is blocked on their session. The main window has `contextIsolation`, `sandbox`, no Node. Keep the preload bridge minimal and validate IPC input in `electron/main.cjs`.
- Device data (`src/devices.js`): viewport sizes in CSS pixels at the default display setting, with a source in mind; don't guess. Keep old device ids (users' saved selections refer to them). Popular sizes come from StatCounter with the month shown; refresh by editing `POPULAR`.
- Themes: dark (default) and light (`data-theme='light'` on `<html>`, toolbar sun/moon button, `state.theme`). Interface colours are tokens in `:root` and `:root[data-theme='light']` in styles.css; never hard-code an interface colour (device hardware colours are shared by both). index.html applies the saved theme before the first paint. Don't use Electron's `nativeTheme` for it: that would change `prefers-color-scheme` for the sites being tested.
- Updates UI: the button at the end of the toolbar (`showUpdate` in main.js). App: states come from electron/main.cjs, and `bezel:update-status` returns the lasting one (downloading, ready) for a page that loads later. Web: compares `version.json` (emitted by vite.config.js) with `__APP_VERSION__` and offers a reload.
- Favorites (`src/address-list.js`): `state.favorites` is `[{ url, title? }]` (title only in the app, from the device view); the address field is a combobox listing favorites then recent sites. Everything persists through storage.js (localStorage, key `bezel:v1`), which survives app restarts and updates.
- Design: dark desk stage, amber accent (#f0a43a), Instrument Sans, realistic device frames. Logo: indigo mark (#575cf5 / #453ace) traced from the user's artwork, `src/assets/logo-mark.svg`, favicon/app icon on a cream tile (`favicon.svg`, `build/icon.png`); README header uses `docs/logo.png`. Plain sentence-case copy, no all-caps labels.
- Phones show a status bar above the page (`statusBarHeight` in frames.js); emulated viewport height is screen minus status bar. No device shows a scrollbar: the app uses `Emulation.setScrollbarsHidden` (Windows laptops and monitors get emulation with `dpr: 0`, which keeps the computer's own density); the web makes the frame one scrollbar wider and clips it.
- Synced scrolling shares a ratio (scrollY over scrollable height), only for user-initiated scrolls. App: `src/sync.js` is injected into each webview and reports through console messages. Web: sites opt in with `public/sync.js` (served at zer0-red.github.io/Bezel/sync.js; keep that URL stable) and talk via `postMessage`; check `event.source` on both sides.
- Device menu (`src/swap-menu.js`): clicking the name under a device opens type → series → device (`SECTIONS`, `SERIES` maps brands to iPhone, Pixel, MacBook…); picking calls `replaceDevice` in main.js, which swaps it in `state.selected` and keeps landscape. Devices already selected are disabled. Cleanup runs on `beforetoggle` (the `toggle` event is queued).
- Checks before pushing: `npm run build`; test the web version in a real browser (Playwright with Chrome) and the app with Electron under xvfb (`--no-sandbox` first in the args). HTTP checks alone are not browser tests. In Electron tests, Playwright's `win.screenshot()` resets the device views' emulation (pixel density drops to 1); measure before screenshots, or capture the screen with `import -window root`.
